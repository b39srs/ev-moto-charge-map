Overview & Design Principles

Tech Stack

  • Database: Supabase (PostgreSQL 15+)
  • Geo: PostGIS extension สำหรับ lat/lng
  • Auth: Supabase Auth (Google OAuth, Email, OTP)
  • Storage: Supabase Storage (avatars, images, documents)
  • Realtime: Supabase Realtime (chat, notifications)
  • Primary Key: UUID (gen_random_uuid())
  • Timestamps: timestamptz (UTC)

Design Principles

  • Privacy-First: ข้อมูลส่วนตัวแยกจาก public data, Progressive Privacy Control ผ่าน trip_member_privacy
  • Phase-Ready: MVP tables พร้อมใช้, Phase 2-3 เพิ่มได้ไม่ต้อง migrate
  • RLS: ทุกตารางใช้ Row-Level Security ควบคุม access
  • Denormalization: เฉพาะ counter fields (member_count, trust_score) เพื่อ performance
  • Soft Delete: ใช้ status field แทนการลบ (trips, members)

Key Relationships
  • profiles 1:N trips (as host), 1:N trip_members, 1:N reviews, 1:N messages
  • trips 1:N trip_members, 1:N messages, 1:N reviews, 1:N expenses, 1:N escrow_transactions

Privacy-First Design Notes
  • ก่อน Join: ผู้ใช้เห็นเฉพาะ display_name, trust_score, average_rating, total_trips_joined, verification_level, badges จาก profiles (ไม่เห็น full_name, avatar, phone, line_id, social_links)

  • RLS Policy: ข้อมูลส่วนตัว (full_name, phone ฯลฯ) จะ return เฉพาะเมื่อ trip_member_privacy อนุญาต

Escrow Flow

pending → held → released
หรือ
pending → held → refunded

Refund Policy: >7 วัน = 100%, 3-7 วัน = 50%, <3 วัน = 0% (ปรับได้ตาม Host)

Trust Score Calculation Formula

trust_score = W1(verification) + W2(trips) + W3(rating) + W4(cancel_penalty)
  • W1 — Verification (0-30): Level 0=0, Level 1=10, Level 2=20, Level 3=30
  • W2 — Trip Experience (0-30): min(total_trips_joined + total_trips_hosted * 2, 30)
  • W3 — Average Rating (0-30): (average_rating / 5) * 30
  • W4 — Cancel Penalty (0 to -20): -(cancellation_count / total_trips * 20)

* Recalculated via DB function after each trip completion / review / verification
